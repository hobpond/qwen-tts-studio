# Story: Reuse an accepted Read Aloud voice for batch generation

## User outcome

When an instruction-driven Read Aloud/Streaming preview produces a voice the user likes, the user can explicitly keep that voice for batch generation. Each batch chunk then uses one captured speaker artifact and does not rerun voice design from the style instruction.

## Tasks

- `TASK-VOICE-REUSE-001A` (done): trace the existing Read Aloud, streaming, voice-design, and batch boundaries.
- `TASK-VOICE-REUSE-001B` (done): materialize the last generated audio as a reusable speaker artifact and retain its provenance in Studio state.
- `TASK-VOICE-REUSE-001C` (done): expose capture/clear/use-for-batch controls and make batch requests prefer the captured artifact.
- `TASK-VOICE-REUSE-001D` (in_progress): add focused tests and portable UI evidence that one accepted voice is used across multiple chunks.
- `TASK-VOICE-REUSE-001E` (done): keep the capture action visible beside the primary Read Aloud controls at compact window sizes.

## Acceptance

- The UI clearly distinguishes “generate a preview” from “keep this voice for batch.”
- Capture requires completed audio and records model/backend/dimension provenance.
- Capture is offered only when the loaded model reports both instruction support and speaker-cloning support; instruction-capable named-speaker models without an encoder are not presented as reusable embedding sources.
- Batch requests use the captured artifact for every chunk and do not pass the VoiceDesign instruction again.
- Changing model identity invalidates or rejects an incompatible captured snapshot rather than silently mixing checkpoints.
- The manifest identifies the captured voice mode/artifact and preserves the source instruction as provenance.
- Existing named-speaker, embedding, ICL, CLI fallback, and streaming playback behavior remains intact outside this opt-in path.

## Current implementation

The Studio screen now offers `Keep voice` after a completed instruction-driven preview. The action is placed in the same primary synthesis action row as Read Aloud/Stream Aloud, so it remains adjacent and discoverable without a full-width weighted row shifting it to the far edge at compact sizes. The view model writes a temporary PCM16 WAV, extracts a speaker-embedding JSON, and passes that fixed path into the existing one-load/sequential batch session. The original instruction is retained only as manifest provenance; it is not resubmitted for each chunk. Desktop tests prove the same artifact path is passed to every chunk and the instruction remains unset.

## Known limitation

The current native API exposes reusable speaker-embedding and full-ICL files, not a first-class “designed voice” handle. The initial implementation captures a speaker embedding from the accepted generated WAV; this freezes speaker identity for batch synthesis, while exact per-utterance prosody is still generated by the model.
